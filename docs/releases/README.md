# Публичные релизы SG Mobile

Каждый GitHub Release должен быть самодостаточным и содержать файлы, относящиеся к одной версии.

Для подготовки описания используйте [готовый шаблон релиза](RELEASE-TEMPLATE.md).

## Обязательные материалы

- подписанный APK;
- файл `SHA256SUMS.txt`;
- номер сборки, versionCode и versionName;
- минимальную версию Android;
- поддерживаемую ABI;
- краткий список изменений;
- известные ограничения;
- указание на совместимость обновления с предыдущей подписью;
- уведомления и лицензионные материалы сторонних компонентов.

## Рекомендуемое имя APK

```text
SG-Mobile-074P-v0.0.93-arm64-v8a.apk
```

Имя должно однозначно показывать продукт, версию и архитектуру. Нельзя заменять опубликованный APK другим файлом под тем же именем.

## Контрольная сумма

Файл `SHA256SUMS.txt` должен содержать полную SHA-256 и точное имя APK:

```text
<64 шестнадцатеричных символа>  SG-Mobile-074P-v0.0.93-arm64-v8a.apk
```

SHA-256 вычисляется только после окончательной подписи APK. Изменение файла после вычисления контрольной суммы недопустимо.

## Порядок публикации

1. Собрать release APK.
2. Проверить unit-тесты, R8 и resource shrink.
3. Подписать APK установленным релизным ключом.
4. Установить APK поверх предыдущей версии.
5. Выполнить чистую установку на тестовом устройстве.
6. Проверить запуск VPN и основные разделы.
7. Проверить встроенную автономную справку.
8. Вычислить SHA-256 уже подписанного APK.
9. Заполнить `RELEASE-TEMPLATE.md` фактическими данными.
10. Создать GitHub Release.
11. Загрузить APK, `SHA256SUMS.txt` и лицензионные материалы.
12. Скачать файлы из опубликованного Release и повторно проверить SHA-256.

До выполнения этих шагов сборка не должна называться публичным релизом.

## Что нельзя загружать

В публичный релиз не входят:

- исходный проект приложения;
- signing keystore и пароли;
- журналы сборочной машины;
- рабочие конфигурации и URL подписок;
- резервные копии пользователей;
- промежуточные ZIP-архивы для разработки;
- непроверенные APK с другой подписью.
